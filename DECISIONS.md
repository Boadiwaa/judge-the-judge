One line each: decision · reason · how to reverse.

- **D-01** Pinned Flet 1.0.5 (latest on PyPI). · Spec says pin and check the API; 1.x core has no chart controls (`LineChart` etc. moved out of core). · Change the pin in `requirements.txt`; re-run the app smoke test.
- **D-02** Charts (CI whiskers, heatmap, 5×5 risk matrix) drawn with plain Flet `Container`s, not a chart library. · Removes a dependency, renders the same on web and mobile, and matches the mockups (dot + line, tiled heatmap). · Swap in `flet-charts` or Plotly images in `src/jtj/app/`.
- **D-03** Omission matching extended: besides the spec rule (judge evidence or span overlaps the omitted original text), a finding also matches if its `transcript_evidence` overlaps (partial ratio ≥ 80) the text of one of the seeded error's `evidence_turns`. · A judge quoting the patient verbatim ("Penicillin. I come out in a rash.") scores only 56 against the note-style original text and would be scored as a miss under the literal rule, which would undercount judges. · `python scripts/compute_metrics.py --strict-spec` writes `*_strict.json` with the spec-literal rule; both are reported. **Approved by Paulina on 2026-10-28, before any judge run (pre-registered). The extended rule is primary; the spec-literal rule is reported as a sensitivity analysis.**
- **D-04** A note with no judge output (parse failure after one retry) counts all its seeded errors as missed, and the failure count is reported per judge. · Conservative; a judge that cannot produce valid output has not detected anything. · Change the `no_output` branch in `src/jtj/metrics.py`.
- **D-05** Spans shorter than 4 characters after normalisation never match. · Stops "OD" or "a" matching anything. · `MIN_LEN` in `src/jtj/match.py`.
- **D-06** Paired McNemar comparisons are computed on High + Very high errors (the primary endpoint population) and on all errors; Holm is applied within each scope across the two comparisons. · The spec says "on the same seeded errors" without naming the subset; doing both is transparent. · Edit `compute_all` comparisons block.
- **D-07** Severity agreement (weighted κ, Gwet AC2) uses judge vs answer-key *severity* (1–5) on detected errors, with ordinal weights for AC2 and quadratic for κ. · Spec names "severity agreement"; tier agreement can be added. · `metrics.py` severity block.
- **D-08** Gwet AC1/AC2 implemented per Gwet (2014); agrees with `irrCAC` 0.4.4 to 1e-4 on identity, quadratic, ordinal and linear weights with missing ratings (tests/test_stats.py). · Spec cross-check requirement. · n/a
- **D-09** Case numbering by setting: 01–04 GP adult, 05–08 ED, 09–12 GP paediatrics, 13–16 mental health, 17–20 outpatient, 21–24 telephone/remote. · Keeps case_07 as the ED ankle case shown in the mockups. · Rename files and ids.
- **D-10** Added two optional fields beyond the spec schema: `case.has_correction` (to check the ≥6 said-then-corrected target) and `mutation.description` (plain-English one-liner for the UI, e.g. "Penicillin allergy dropped from an ED note"). · Needed by the validator and the "Most dangerous misses" list. · Both default to empty/false; delete freely.
- **D-11** Cases are authored with a throwaway helper that resolves evidence turns from quoted text anchors; the JSON files in `data/cases/` are the single source of truth and can be edited directly. · Hand-counted turn numbers were wrong in the first draft; anchors fixed them. · n/a

- **D-13** In J0 the output schema is still given (so it can be parsed), but with free-text error types and no rubric or anchors. Its types map to `UNSPECIFIED`. · Spec §5.3. · `J0_SCHEMA` in `judges.py`.
- **D-14** Judges run on open-weight models served locally by llama.cpp (`llama-server`, build 11669), not the Anthropic API. Default model is Gemma 4 E2B instruct, Q4_0 GGUF. The web app is unaffected: it still only reads precomputed JSON. · Paulina's choice, 2026-10-28. · Set `JUDGE_PROVIDER=anthropic` and `ANTHROPIC_API_KEY`; the Anthropic path is kept.
- **D-15** Judge outputs are filed per model (`data/judge_outputs/J1_<model>/`), and `compute_metrics.py --model <name>` picks which model's outputs to score. The server is started with `--alias <model>`, and `run_judges.py` refuses to run if the served model doesn't match `JUDGE_MODEL`, so outputs can't be filed under the wrong model's name. · Makes the two-model comparison possible and stops mix-ups. · n/a
- **D-16** Local runs use schema-constrained decoding (llama.cpp `response_format: json_schema`) and cap findings at 25 per note. · With the schema applied but no item cap, MedGemma 1.5 4B (Q3_K_M) repeated one bogus finding about 200 times until it hit the token limit, so the note failed to parse even after the retry. The cap applies equally to every model. · `MAX_FINDINGS` and `JUDGE_JSON_SCHEMA` in `judges.py`.
- **D-17** Local decoding: temperature 0, fixed seed 20261028, context 16,384 tokens, all layers on the GPU (`-ngl 99`), the model's own chat template (`--jinja`). Gemma 4 produces hidden reasoning tokens before its answer; only the final answer is stored. · Reproducibility; Gemma 4 needs `--jinja` (from the TalkingLabs notes). · Server flags in README/DEPLOY.
